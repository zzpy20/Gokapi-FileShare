IP Change Checklist

Run this the moment the ECS's public IP changes. Fixing the one broken setting takes under a minute — the rest is just knowing what doesn't need touching.

If this is Same instance, IP just reassigned

Rare on Aliyun unless you released and re-bound the elastic IP yourself. Everything below applies directly — start at step 1.

If this is A brand-new ECS instance

What's happened before (e.g. the sing-box rebuild after an IP ban) — none of the three apps exist on the new box yet. Follow Part 3: New Box, Same Stack first, then come back here for step 3 only.

Point the SSH hostname at the new IP

DNS provider for 1000600.xyz

shenzhen.1000600.xyz currently resolves to the box's IP, and that's the hostname your ~/.ssh/config uses for the sz alias — not the raw IP. Update that A record and ssh sz keeps working with nothing to change locally.

Skip this and ssh sz will silently connect to the old, dead box.

Open the ports on the new Security Group

Aliyun console

ECS → Security Groups → Configure Rules → add inbound TCP for each, source 0.0.0.0/0:

22    (SSH)
8080  (fileshare)
9000  (quickshare-sz)
9001  (gokapi)

A new instance starts with a fresh security group — none of this carries over from the old box automatically, even if the IP swap felt instant.

Fix Gokapi's saved URL

on the server — ssh sz

Gokapi is the only one of the three that bakes the IP into a config file, because it uses that value to build every share link it generates from here on.

ssh sz 'sed -i "s|http://OLD_IP:9001/|http://NEW_IP:9001/|" ~/gokapi/config/config.json \
  && docker restart gokapi'

fileshare and quickshare-sz need nothing here — both build every link from the request itself, not a saved setting.

Re-send the links

to whoever's expecting a file

Anyone holding a link with the old IP in it now has a dead link — that's just old text, no server-side fix reaches it. The base addresses are:

Browsable folderhttp://NEW_IP:8080/
Private linkshttp://NEW_IP:9000/
Expiring linkshttp://NEW_IP:9001/admin

Individual quickshare-sz and Gokapi file links need regenerating from their admin pages — the id/filename stays the same, only the host part changed.

Worth knowing

This whole checklist exists because the box deliberately uses a bare IP instead of a domain, to dodge mainland China's ICP filing requirement for anything reachable at a domain name. That trade-off is what makes IP changes disruptive in the first place — see the original setup notes if you ever want to reconsider it.
