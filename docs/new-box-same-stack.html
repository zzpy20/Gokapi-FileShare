Shenzhen file-share stack · Part 3 of 3

New Box, Same Stack

Both apps are plain Docker Compose services with local bind-mount volumes — no shared database, no cloud storage, nothing else to migrate. Replicating one is copying four things and running one command.

Throughout this page, newbox stands for however you reach the new server — either an alias you've set up in ~/.ssh/config, or just root@its.ip.address. Swap in whichever applies to you. Commands marked "on your Mac" run in a normal Terminal window on your own computer, where you already have the Gokapi-FileShare repo cloned; commands marked "on the new box" run after you've SSH'd in.

fileshare :8080

Install Docker

on the new box 
sudo apt update && sudo apt install -y docker.io docker-compose-plugin
sudo systemctl enable --now docker

Skip this if the box already has Docker — check with docker --version first.

Copy the fileshare folder over

on your Mac 
rsync -a ~/Projects/Gokapi-FileShare/fileshare/ newbox:~/fileshare/

Brings the Dockerfile, docker-compose.yml, and source. Add --exclude shared if you don't want to also carry over whatever files are currently in your local copy.

Set the upload password

on the new box 
cd ~/fileshare
cp .env.example .env
nano .env

Change UPLOAD_USER and UPLOAD_PASS to real values, then save (in nano: Ctrl+O, Enter, Ctrl+X).

Build and start it

on the new box 
docker compose up -d --build
Expect to see: Successfully built ... followed by Container fileshare Started. Builds from the official python:3.12-alpine image, which pulls normally anywhere — mainland China included.

Confirm it's running

on the new box 
docker ps --filter name=fileshare
The STATUS column should say Up. If it says Restarting instead, run docker logs fileshare to see why — the most common cause is forgetting step 3.

Open the port

firewall / security group

Allow inbound TCP on port 8080 from 0.0.0.0/0 — in Aliyun's console under ECS → Security Groups, or with sudo ufw allow 8080/tcp if the box uses ufw.

gokapi :9001

Same shape as fileshare, with one extra fork partway through. Don't try to guess in advance which branch you need — step 4 tells you how to tell, from what actually happens when you try the simple version first.

Install Docker

on the new box 
sudo apt update && sudo apt install -y docker.io docker-compose-plugin
sudo systemctl enable --now docker

Skip this if the box already has Docker — check with docker --version first.

Copy the gokapi folder over

on your Mac 
rsync -a --exclude bin --exclude data --exclude config \
  ~/Projects/Gokapi-FileShare/gokapi/ newbox:~/gokapi/

Brings both compose files (docker-compose.yml and docker-compose.china.yml), the Dockerfile, and fetch-binary.sh. The three excluded folders are either build output or per-instance state — nothing you want copied from your laptop.

Try the simple version first

on the new box 
cd ~/gokapi
docker compose up -d

This pulls the official f0rc3/gokapi image straight from Docker Hub — no build step, works everywhere except mainland China.

Check what happened

on the new box 
docker ps --filter name=gokapi
STATUS says "Up" → it worked. Skip straight to step 7.
Command errored out instead, mentioning 403 Forbidden or failed to resolve reference → this network blocks the image, same as the Shenzhen box. Continue to step 5.

Fetch the binary directly instead

on your Mac

Only needed if step 4 showed the blocked error. This downloads Gokapi's release straight from GitHub — no Docker Hub involved.

cd ~/Projects/Gokapi-FileShare/gokapi
./fetch-binary.sh
Creates a new bin/gokapi file locally. You'll see Done: ./bin/gokapi when it finishes.
Then copy it to the new box
scp -r bin newbox:~/gokapi/bin

Build the local image and start it

on the new box

Only needed if you did step 5. This builds a small image wrapping the binary you just copied over, instead of pulling one.

cd ~/gokapi
docker compose -f docker-compose.china.yml up -d --build
docker ps --filter name=gokapi
Same check as step 4 — STATUS should say Up.

Open the port

firewall / security group

Allow inbound TCP on port 9001 from 0.0.0.0/0 — same place you opened 8080 for fileshare.

Finish setup in the browser

from any computer

Visit http://<new box's IP>:9001/setup and click through the wizard. Recommended choices, same as the original Shenzhen setup:

Database:            SQLite (leave the default path)
Bind to localhost:   No
Use SSL:             No
Log IP on download:  No
Include filename:    Yes
Encryption Level:    Level 1 - Local encryption / Key locally

On the Credentials screen, set a real admin username and password — this is the login you'll use at /admin from now on.

Confirm it's reachable

from any computer 
curl -I http://<new box's IP>:9001/
Expect HTTP/1.1 200. If it hangs or times out, double-check step 7 — the port is almost always the culprit at this stage.

Carrying over existing data

Two honest options, not a default to feel bad about skipping.

Fresh start

Don't copy data/ or config/ — both apps happily initialize empty. Gokapi will ask you to run /setup again; fileshare needs no setup step at all.

Same files, same links 
rsync -a ~/gokapi/data/ newbox:~/gokapi/data/
rsync -a ~/gokapi/config/ newbox:~/gokapi/config/

Carries over admin credentials and every file too. Do this and you still need one more edit —

Don't forget

If you copied Gokapi's config/ across, its saved ServerUrl still points at the old box's IP — every link it generates will be wrong until you update it. Same one-line fix as an IP change: see Part 1, step 3.

That's the whole migration. No database to export, no cloud storage to reconnect — two folders, two docker compose up calls, one firewall rule per app.
