Where Your Files Live

Three apps, three different answers. This is the host path behind each link, how to add or remove something by hand, and what happens to it over time.

fileshare

:8080

The browsable folder — a directory listing, nothing hidden.

Host path
~/fileshare/shared/ — real filenames, real subfolders, exactly as they sit on disk.
Add a file
scp yourfile.pdf sz:~/fileshare/shared/
or drag-and-drop at the password-gated /upload page.
Remove a file
ssh sz 'rm ~/fileshare/shared/"yourfile.pdf"'
List everything
ssh sz 'ls -la ~/fileshare/shared/'
Retention
Forever, until you delete it by hand — no expiry feature exists here.
Currently
216 KB across 2 files and 1 folder

quickshare-sz

:9000

One-off private links — no listing, the link is the only way in.

Host path
~/quickshare-sz/data/<id>/<filename> — every upload gets its own folder, and that random 12-character folder name is the id in the link.
Add a file
Only through the web upload page at :9000, pasting the upload key. The id has to come from the app itself, so there's no SSH shortcut for this one.
Remove a share
ssh sz 'rm -rf ~/quickshare-sz/data/<id>/'
List all shares
ssh sz 'ls ~/quickshare-sz/data/'
then look inside each folder for the filename.
Retention
Forever, no expiry — same as fileshare, just link-shaped instead of browsable.
Currently
5.7 MB across 9 shares

gokapi

:9001

Expiring links with a real admin UI — the only one of the three you don't manage by hand.

Host path
~/gokapi/data/ — but files are encrypted at rest, so what's actually there is opaque hash-named blobs, not readable names or content.
Manage it
Everything happens at http://<ip>:9001/admin — upload, delete, view download counts, set expiry by date or by download count. There's nothing useful to do here over SSH.
Metadata
~/gokapi/data/gokapi.sqlite — don't hand-edit this; use the admin UI.
Retention
Whatever expiry you set per file at upload — this is the only one of the three with real expiry.
Currently
3.7 MB across 3 uploads
To wipe an app completely

Irreversible — stop the container first, then clear its data directory and restart. Layouts differ, so do it per app:

ssh sz 'cd ~/gokapi && docker compose down && rm -rf data/* config/* && docker compose up -d'

Gokapi will ask you to run through /setup again afterward. fileshare and quickshare-sz just need their shared/ or data/ folder emptied the same way — no setup step to redo.
